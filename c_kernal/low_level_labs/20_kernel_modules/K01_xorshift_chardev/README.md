# K01 — `/dev/nm_xorshift` char device

## Goal
Build an out-of-tree Linux kernel module that exposes a character device at `/dev/nm_xorshift`. `read()`s return random bytes generated by an in-kernel port of `cpp/numerical_methods/c/xorshift.c`. No floating point.

## Why this is interesting
Your first LKM. You'll learn:
- The `file_operations` table
- `cdev_init`, `cdev_add`, `class_create`, `device_create` boilerplate
- The userspace ↔ kernel boundary: `copy_to_user`
- Why kernel C is *not* userspace C (no libc, no float by default, careful with stack)
- Building, loading (`insmod`), unloading (`rmmod`), watching (`dmesg -w`)

## Prereqs
- `00_setup/` complete (linux-headers installed)
- Read the LKMPG (`sysprog21/lkmpg`) chapters 1–4 first

## What to do
1. Author `nm_xorshift.c` (kernel module source) and `Kbuild`.
2. The module:
   - Allocates a major number with `alloc_chrdev_region`
   - Initializes a `struct cdev` and registers `file_operations` with a `read` callback
   - Creates a class and device so udev populates `/dev/nm_xorshift`
   - The `read` callback: pull next uint64 from xorshift state, `copy_to_user`, return bytes-written
   - State: a single `u64` static, protected by a spinlock (or per-CPU; explicit choice in writeup)
3. Build: `make`
4. Load: `sudo insmod nm_xorshift.ko`
5. Test: `dd if=/dev/nm_xorshift bs=8 count=4 | xxd`
6. Unload: `sudo rmmod nm_xorshift`
7. **Compare** the kernel output against the userspace reference. Build `xorshift.c` from `cpp/numerical_methods/c/` into a `.so`, `ctypes.CDLL` it from `python/bindings.py`, seed both with the same value, assert identical byte streams.

## Measurable outcome
- Module loads cleanly (`dmesg` shows registration message, no warnings)
- `cat /dev/nm_xorshift | head -c 64 | xxd` shows random bytes
- `pytest python/test_lab.py` passes — three-way oracle (kernel == userspace C == Python ctypes)
- Module unloads cleanly (no kernel taint, no leaked refcounts)

## Reuse
- `cpp/numerical_methods/c/xorshift.c` — port the algorithm, drop libc dependencies
- Recommendation: extend `cpp/numerical_methods/include/c_api/nm_inline.h` with an `NM_KERNEL` macro that expands to `static inline` and disables FP. Include the shared algorithm body from kernel-module source.
